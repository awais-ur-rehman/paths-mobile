# Likes redesign

Owner delegated research, final design and implementation. Preserve the private-save/request/explicit-accept model. Research: Hinge official Likes guide https://help.hinge.co/hc/en-us/articles/36311632894995-Likes separates incoming interest and matches, while Bumble https://bumble.com/en/help/why-did-my-liked-you-number-decrease-when-i-purchased-bumble-premium explains that filters hide nonmatching people. Adopt visible relationship sections and explicit/resettable filters; do not import subscriptions, ranking/online claims or dating-specific business rules.

White Paths screen: concise Likes title, pill name/username search, four visible sections Saved/Requests/Sent/Connected. Original icons, blue selection, existing gray bottom navigation. Rounded two-column authenticated photo cards show names, verification and one concise status. Tap opens the existing profile; existing request/accept/message rules remain there. No fake totals. Unavailable saved profiles remain removable. Pull refresh and lazy cursor paging, loading/empty/offline/retry and cancellation retained.

Search is server-side across all pages, not just loaded cards. Case-insensitive literal name/username search (max100), Verified-only, optional Pending-only on request sections. All records remain the default, preserving history. Filters reset cursors and bind into signed cursors alongside actor/section. Never match hidden profile fields for unavailable members. Effective pending excludes expired requests. Contract1.14.0 shared across all clients; no migration/dependency. Continue existing draft branches while prior API/UI work remains unmerged; update their final descriptions. No main merge, device operation, iOS build or download.

Admin guide: create documents/ADMIN_LOGIN.md and a publishable copy in paths-admin/docs. Verify existing local test staff account/enrollment using password+MFA and logout, without exposing secrets, rotating credentials, changing grants or creating fake users. Guide records email/URLs/private file locations and setup steps, never passwords/TOTP seeds. Backend/admin source otherwise unchanged beyond API contract consumers.
